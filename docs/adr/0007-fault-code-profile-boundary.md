# 故障码表独立于车辆类型

故障手册按厂家、车型和协议版本拆分，现有 `vehicleType` 编码不足以唯一确定故障码含义。车辆类型继续负责选择 CAN 协议解析器，车辆另关联故障码表编码；故障翻译按“故障码表编码 + 故障码”匹配。每个具体车型或车型协议版本维护独立故障码表，即使不同车型的故障定义相同也允许重复保存，不做跨车型共享。

第一阶段将 `faultState` 作为单个精确故障码处理：`0` 表示无故障，非零值按“故障码表编码 + 故障码”查询；未匹配的故障码保留原值并标记为未知，除非后续协议资料明确说明该字段是位图，否则不拆分为多个故障。

故障码定义作为独立 GCAN 业务资料建模，不放入通用系统字典；故障码表保存一个具体车型或车型协议版本，故障码定义保存等级、名称、解析、表现、恢复、解除和处理建议等详细资料。手册中覆盖多个车型的工作表在导入时拆分并复制到各自故障码表。

车辆档案显式关联一个故障码表编码，实时故障翻译使用该关联，不根据 `vehicleType` 自动推断；未配置故障码表时仍保留原始故障码，并标记为未配置故障码表。

第一阶段故障码表只服务于实时故障翻译，不对 CAN 历史帧保存故障码表版本或解析结果；故障码表的后续修改不回溯历史原始帧。需要历史故障追溯时另行引入故障事件和版本快照。

故障码表和故障码定义支持启用/停用，不允许删除正在被车辆使用的故障码表；停用的故障码表不能被新车辆选择，停用的故障码定义仍保留原始故障码并标记为未启用。

不同车型手册中的故障等级原样保存，不强行把“致命/严重/一般”和“I级/II级”等表达归并为同一语义；大屏第一阶段展示原始等级名称，统一颜色或严重度映射待规则明确后再增加。

故障码明细第一阶段保存故障码、原始等级编码和名称、故障名称、定义、解析、表现、恢复、解除、处理建议、备注及启用状态；不同手册才有的触发条件或内部信息先归入备注，不设计动态字段。

开放 API 保留原始 `faultState`，并新增结构化 `fault` 结果，区分无故障、未配置故障码表和未知故障码；详情字段可为空，以兼容不同车型资料完整度。

只有收到有效 CAN 快照并解析出 `faultState = 0` 时才表示无故障；暂无数据或未支持解析不生成无故障结果，离线车辆保留最近一次有效故障结果并标记数据已过期。

故障码表关联为可选，不阻塞车辆启用和数据采集；未关联故障码表时，实时 API 仍返回原始故障码，并标记未配置故障码表。

故障码表编码由后台人工维护，创建后不可修改或重复；故障码表名称、厂家、适用车型说明和备注可维护。车辆档案与开放 API 使用该稳定编码，不使用数据库 ID 或手册工作表名称作为外部标识。

在不同车型故障等级语义尚未统一前，大屏对所有已匹配活动故障使用统一故障提示色；未知故障码和未配置故障码表使用警示色，不按原始等级名称直接推导跨车型严重度颜色。

故障手册的 Excel 作为后续整理详细资料的主来源，PDF 作为补充和校对来源；第一阶段不做文件导入，故障码表和故障码定义通过后台维护，车辆档案显式选择故障码表。
