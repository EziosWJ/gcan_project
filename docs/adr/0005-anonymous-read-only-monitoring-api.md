# 对外监控 API 暂采用匿名只读访问

监控大屏和第三方系统需要访问车辆实时监控数据；当前阶段对外 API 采用匿名只读方式，以降低接入成本。接口不开放车辆档案写入和状态变更，但允许读取全部实时快照字段、GCAN 盒子标识、当前原始 CAN 帧和分页查询的 CAN 历史数据；历史数据必须通过分页和筛选读取。这会增加数据暴露面和接口响应体积，后续如接入方和部署环境需要，再增加独立客户端凭证与访问控制。

开放查询接口使用独立的 `/api/open/gcan/v1` 命名空间，与后台管理接口分离，避免开放配置误覆盖车辆档案等写入能力。

CAN 历史开放查询必须提供开始和结束时间，单次最多查询 24 小时；默认页大小为 50，最大为 200，并支持按车辆、煤矿和 CAN ID 筛选，以控制匿名查询的数据量。

监控大屏使用独立的监控总览查询，在服务端完成启用车辆补齐、实时快照关联、煤矿分组和在线状态统计；原始 CAN 数据通过独立查询按需读取，不嵌入总览响应。

独立监控大屏允许匿名访问，不经过后台管理登录态；页面只调用开放查询接口，不提供任何写入能力。

开放接口的 CORS 第一阶段使用默认通配符 `*`，因为接口匿名且不依赖登录 Cookie；这降低浏览器接入成本，但意味着任意来源页面都可读取已公开的监控数据。

第一阶段不对匿名开放接口增加 API Key 或访问限流，仅通过总览轮询约定、历史查询时间跨度和分页上限控制使用方式；后续流量增长或数据暴露风险上升时再补充访问控制。

开放接口统一使用 `/api/open/gcan/v1` 版本前缀；`v1` 遵循只增不删和不改变既有字段语义的兼容策略，破坏性变更进入新版本，并提供 OpenAPI 契约文档。

开放接口沿用项目现有 `ApiResponse` 响应包络，成功数据和错误语义与后台 API 保持一致。

监控总览提供全局统计和煤矿分组统计，至少包含车辆总数、在线数、离线数、暂无数据数、未支持解析数、故障车辆数和最近数据更新时间。

全局当前故障数只统计在线且有有效快照、故障码非零的车辆；离线车辆保留最后已知故障但不计入当前故障数，暂无数据和未支持解析车辆也不计入。

第一阶段开放查询端点包括监控总览、平铺实时快照、当前原始 CAN 帧、分页历史 CAN 帧和 GCAN 字典查询；故障码表维护及车辆故障码表关联属于后台管理能力，不纳入匿名开放写入范围。

大屏每 3 秒只轮询监控总览；当前原始 CAN 帧和历史 CAN 帧按需查询，煤矿、车型和状态名称由总览直接返回，避免大屏常态刷新产生多个字典请求。

监控总览按字典顺序稳定排列煤矿、按车辆名称和档案 ID 稳定排列车辆，不因状态变化动态重排；大屏的煤矿和卡片折叠状态由前端保留，轮询刷新不重置用户当前展开状态。

开放 API 的煤矿、车型和状态字段同时提供稳定编码与展示名称，使匿名大屏和第三方系统无需依赖后台登录态字典接口即可展示数据。

数值字段保持数值类型，单位与数值分离，并在接口契约中统一定义：电压为 V、电流为 A、温度为 ℃、电量及开度为 %、车速为 km/h、旋转速度为 rpm、里程为 km；协议未赋值的字段返回 `null`，不使用伪造的默认值。
