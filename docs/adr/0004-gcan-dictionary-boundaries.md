# GCAN 字典边界

Status: accepted

GCAN 车辆档案中的煤矿和车辆类型使用系统字典项值作为稳定编码，但字典主数据仍归 `system-api` 管理，`gcan-api` 不直接依赖 `system-api` 的实现模块或字典表。前端负责把煤矿编码和车型编码翻译成显示名称，`gcan-api` 只保存和过滤编码；煤矿维护与车型管理可以作为 GCAN 菜单下的专用入口复用字典接口。

车辆类型字典允许先新增未来车型，解析器不再通过集中 enum 逐项锁死车型，而由每个协议解析器声明自己支持的车型编码；匹配前统一按大写形式比较，避免人工录入大小写导致解析失败。字典中存在但尚无解析器支持的车型可以用于车辆建档，原始 CAN 帧和 CAN 历史数据仍可记录，但车辆 CAN 状态应明确表现为未支持解析。

CAN 历史数据只保存车辆/盒子、CAN ID、数据和接收时间等 CAN 事实，不冗余煤矿、车型或车辆名称；按煤矿、车型查询历史时通过当前车辆档案关联过滤。这个取舍保持历史表简洁，也符合煤矿只是业务筛选维度、不影响 CAN 存储事实的约定。
